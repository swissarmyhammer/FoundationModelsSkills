## What
Three related variances at the SearchSkill/SkillSearchAgent seam:

1. **No model-surface filtering at dispatch** (§6 "filtering is applied by the operation implementations"; §7 "over the model-visible catalog"): `SearchSkill.execute` returns whatever the searcher holds, never applying `context.visibilityPredicate` (`Operations/SearchSkill.swift:112-121`). `ListSkill` (`ListSkill.swift:85`) and `UseSkill` (`UseSkill.swift:123`) do filter. Fix: filter search matches through the context predicate before building rows.
2. **`SearchSkillResult.total` is the truncated count** (§7: total exists "so the model knows to raise limit"): `total: rows.count` post-cap (`SearchSkill.swift:119-120`, `Search/SkillSearchAgent.swift:32-35`). Fix: report the real match count before the `limit` cap.
3. **`update(items:)` hardcodes the model surface** (§7.2: the CLI is a user, not a model): `SkillSearchAgent.update` filters on `isModelVisible` unconditionally (`SkillSearchAgent.swift:50-52`), so a user-surface agent (as the CLI builds from `commandListing()`, `CLI/SkillsCLI.swift:44-49`) silently flips to the model subset on first reload. Fix: the agent takes its visibility filter at init (defaulting to model-visible) and applies that same filter in `update(items:)`.
