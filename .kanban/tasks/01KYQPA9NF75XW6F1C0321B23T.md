## What
Variance from §7.1 (one registry, four simultaneous consumers) and §6 ("commandUpdates ticks on every reload"): `onReload` is a single `AsyncStream` with one continuation (`Registry/SkillsRegistry.swift:154, 274-284, 836-840`), and `commandUpdates` CONSUMES that same stream (`Registry/SkillsRegistry+SlashCommands.swift:49-59`). Two `for await` consumers split elements — a host that forwards metadata to the searcher AND reads `commandUpdates` loses an arbitrary share of ticks on each side; each fresh `commandUpdates` access adds another competing consumer.

Fix: multicast reload events — e.g. keep a locked array of continuations, each `onReload`/`commandUpdates` access registers its own stream, every rebuild publishes to all registered continuations (and finishes them on deinit). Update the single-subscriber doc comment (`+SlashCommands.swift:44-48`).
