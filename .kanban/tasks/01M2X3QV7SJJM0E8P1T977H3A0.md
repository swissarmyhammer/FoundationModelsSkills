title: Put both spawn paths on the Extras process runner, and give the shell pass its limits
---
## What

This package starts a process in two places, and the two do not have the same safety.

- `Sources/FoundationModelsSkills/Resources/ScriptProcessRunner.swift` — a process group, a timeout, `SIGKILL` of the group, and the tail of the output. Used by `run script`.
- `Sources/FoundationModelsSkills/Render/ShellInjection.swift:203-214` — `Process()` with `/bin/sh -c`, then `readDataToEndOfFile()` and `waitUntilExit()`. **No timeout. No limit of the output. No process group. No kill.**

Thus a `` !`sleep 1000` `` in the body of a skill stops the render for ever, and a command that writes without end fills the memory of the host. The `run script` path is safe; the render pass is not. Also, neither path registers its pid with `ProcessRegistry.global` of `FoundationModelsExtras`, which is the backstop of the family against a leaked group.

1. Delete `Resources/ScriptProcessRunner.swift`. Use the `ProcessRunner` of Extras (card ^86z4bmc on that board), which holds the group, the timeout, the caps and the registry.
2. `RunScript` calls `ProcessRunner`. Its behavior, its result fields and its correctives do not change.
3. `ShellInjection` calls `ProcessRunner` also, and it gets the limits that it never had:
   - a timeout for each command, with a default that this package sets;
   - a limit of the bytes of the output;
   - the process group and the kill.
4. **What the render shows when a command fails a limit.** The pass writes the same inert marker that it writes when the policy turns the shell off, with the reason. It does not write the partial output, and it does not stop the render of the rest of the body.
5. The timeout and the byte limit are fields of `RenderPolicy`, thus a host can change them, and the default is safe.

## Acceptance Criteria

- [ ] No file of this package spawns a process; both paths call the Extras `ProcessRunner`.
- [ ] A shell command that passes the timeout does not stop the render: the pass writes the marker and the render continues.
- [ ] A shell command that writes more than the byte limit does not grow the memory: the read stops at the limit.
- [ ] After a timeout, no child of the command is alive.
- [ ] `run script` gives the same results as before, with the same fields and the same correctives.
- [ ] The default timeout and the default byte limit are in `RenderPolicy`, and a host can change them.
- [ ] `swift build --build-tests` gives 0 warnings, and `swift test` is green.
