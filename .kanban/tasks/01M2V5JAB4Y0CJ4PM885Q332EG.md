title: A skills search result must tell the model to use a skill that applies, and how
---
## What

In the SWE-bench run of 2026-09-18 15:42 in `FoundationModelsACPAgent` (instance `django__django-13447`), the `skills` search worked, but the model did not use a skill.

- The model called `skills` with `{"op": "search skill", "query": "build app dict admin views"}`.
- The search returned four matches: `detected-projects`, `explore`, `code-context` and `map`, each with its `id`, `description`, `parameters` and `source`.
- The model never called `use skill`. Its next reasoning was "Let's explore the project", and then it called `tools.files.glob`. It read the list as information, not as a step to do.
- Thus the model never got the procedure of `explore` or `code-context`, and it made 0 `tools.code_context` calls.

The result of `search skill` is a menu. It does not say that a skill that applies must be used, and it does not say how to load one. In the same run the model obeyed the `next` text of `runCode` 28 times, thus a clear instruction in the result is followed.

## The work

1. **Each match carries the call that loads it.** `SkillRow` of `search skill` gets a `use` field with the exact arguments of the `skills` tool:

   ```json
   { "id": "explore", "description": "Understand how unfamiliar code works …", "use": { "op": "use skill", "id": "explore" } }
   ```

2. **The result carries one plain instruction.** `SearchSkillResult` gets a `next` field. Use this text:

   > If a skill in this list applies to your task, you must use it. Load it now with its `use` call, and follow its instructions before you continue with the task.

   When the result has no match, it has no `next` field. The result must never tell the model to load a skill that is not there.

3. **The first match comes back with its body when the selection tier chose it.** When the selection tier (not the retrieval fallback) gives the first match, the result also carries the rendered body of that one skill, with the same render path as `use skill`. Then `next` is:

   > The first skill is loaded below. If it applies to your task, you must follow it. If a different skill applies, load it with its `use` call.

   When the answer comes from the retrieval fallback, the result has no body, and `next` is the text of item 2. A body is given for the first match only, to keep the result small.

4. **Tests.**
   - Each match has a `use` field whose `op` resolves to `use skill` and whose `id` is the id of the match.
   - A result with matches has the `next` text of item 2. A result with no match has no `next`.
   - A selection-tier answer gives the body of the first match and the `next` text of item 3. A retrieval-fallback answer gives no body.
   - The body in the search result is the same text that `use skill` gives for that id.

5. **Documents.** `docs/operations.md` shows the new output of `search skill`. The CHANGELOG records the new fields. The output is JSON for a model, thus the change breaks no host source.
