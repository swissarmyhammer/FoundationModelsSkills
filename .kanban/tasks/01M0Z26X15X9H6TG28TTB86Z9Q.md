    ### Cause found and recorded

    Evidence (probe run with `SKILLS_INTEGRATION_TESTS=1`, transcript of the live session):
    - `(Prompt) read the contents of a file`
    - `Response Format: <nil>`
    - `(Response) [toolA]`
    - error: `Encountered content that cannot be completed into valid JSON  Text: [toolA]`

    The cause is a dispatch fault in the dependency `FoundationModelsRanker`, not in the model and not in the prompt:
    - `AgentSession` (FoundationModelsRanker/Selection/AgentSession.swift) declares only `respond(to:)` and `fork()` as protocol requirements. The typed `respond(to:generating:)` is an extension method with no requirement behind it.
    - `SelectionTier` holds each session as `any AgentSession` and calls `respond(to:generating:)`. Through the existential, Swift dispatches that call statically to the extension default: plain `respond(to:)`, then `GeneratedContent(json:)` over the raw text.
    - The guided override in `LanguageModelSessionSupport.swift` (`extension LanguageModelSession: AgentSession`) is never reached through the existential. The same call on a concrete `LanguageModelSession` does reach it (probe: `Selection(ids: ["toolA"])`).
    - Without a response format, the on-device model answers `[toolA]` in free text. `GeneratedContent(json:)` cannot complete that into the `{"ids": [...]}` object, so the decode throws.

    Fix in this package (test target, `Tests/FoundationModelsSkillsTests/HotReloadLiveTests.swift`):
    - New `GuidedSelectionSession: AgentSession` wraps the live `LanguageModelSession`. Its `respond(to:)` (the one method the protocol dispatches dynamically) asks the session for a `Selection` through native guided generation and returns `generatedContent.jsonString`. The extension default then decodes a schema-conforming object.
    - `SelectionConfig.model` in the test now returns that wrapper.
    - Result: `SKILLS_INTEGRATION_TESTS=1 swift test --filter HotReloadLiveTests` passes (1 test, 1.7 s).

    Dead end: a change to the prompt or to the `@Generable` schema cannot help, because no response format reaches the model on that path.
