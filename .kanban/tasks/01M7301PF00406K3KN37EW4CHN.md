## What
Part of SK-6 (D87 (d), D175). Add the file logic of the three writes, with no tool code. Create `Sources/FoundationModelsSkills/Registry/SkillWriter.swift`:
- `public enum SkillWriteLayer: String, CaseIterable, Sendable { case user, project }`. The default is `.user` (D175). Keep the name `layer` and the values `user` and `project` the same as the `agents` tool (AG-9, FoundationModelsAgents).
- The target root: the highest-precedence layer of the registry with `DotfolderStack.Source` `.user` or `.project`. In the app the user layer is `<iCloud container>/Documents/Agents/_skills/` and the project layer is `<cwd>/.skills/`. The host gives these roots through the `DotfolderStack`. The writer does not compute them. Today `SkillsRegistry` keeps only `roots: [URL]`, thus add `public let layers: [DotfolderStack.Layer]` to `SkillsRegistry`.
- `add(name:skillMarkdown:layer:)`: makes `<root>/<name>/SKILL.md`. Refuse when the folder already exists in that layer. Validate `name` (one path component, no `..`, no `/`) and the frontmatter with `SkillValidator` before the write.
- `edit(name:path:content:layer:)`: writes `SKILL.md` or a file of the skill. The path must stay inside `<root>/<name>/` (use the same path rules as `ReadResource`). The skill folder must exist in the target layer. When the skill is only in a read-only layer (`.defaults` or `.marketplace`), `edit` refuses with a corrective that names the read-only layer and tells the model to use `add` with the same name in a writable layer to override it.
- `remove(name:layer:)`: deletes `<root>/<name>/`. Refuse when the folder is not in that layer.
- A layer that the registry does not have gives a corrective, not a crash. Note: a registry from `init(roots:)` labels each root `.project` (`untrustedLayers(for:)`), thus it has no `.user` layer. Document this in the doc comment.
- After each successful write, call `registry.reload()` (SK-6a).
- No gate (D78, D87).

## Acceptance Criteria
- [ ] `add` makes the folder and `SKILL.md` in the user layer by default, and in the project layer with `.project`.
- [ ] `edit` and `remove` change only the chosen layer. A built-in or marketplace layer is never written.
- [ ] A bad name, a path out of the skill folder, a skill that is only in a read-only layer, or a missing layer gives a corrective and writes nothing.
- [ ] After each write, `registry.metadata()` shows the change, and one `onReload` value arrives.

## Tests
- [ ] `Tests/FoundationModelsSkillsTests/SkillWriterTests.swift` with `LayerFixtureSupport`: a stack with defaults, user and project layers in temp folders. One test for each operation and each layer, one for each refusal, and one that the defaults folder is unchanged after each operation.
- [ ] `swift test` passes with no warnings.
