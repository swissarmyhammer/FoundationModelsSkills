title: use skill must give the text of the skill, not JSON
---
## What

In the SWE-bench run of 2026-09-19 07:28 in `FoundationModelsACPAgent` (instance `django__django-13447`), the `skills` output was hard for the model to read:

- `use skill` gives JSON: `{"body": "…", "id": "explore"}`. The procedure is an escaped JSON string (`\n`, `\/`), not text.
- `search skill` gave one JSON object of 9,343 characters. The body of the first match was inside it as an escaped string, after the list of matches. Its one instruction said "The first skill is loaded below", but a JSON object has no clear "below".

The model called `search skill`, got `explore` first with its body, and still did not follow it. It made 0 `tools.code_context` calls.

## The work

1. **`use skill` gives plain text.** The answer of `{"op": "use skill", "id": "<id>"}` is the rendered markdown body of the skill, and nothing else: no JSON, no `body` key, no `id` key, no escaping, no tag or wrapper.
2. **An error of `use skill` stays a plain sentence** (for example an unknown id, or a missing argument). It says what is wrong and names the valid ids.
3. **Tests.**
   - The answer of `use skill` is equal to the rendered body, character for character.
   - The answer holds no JSON structure around the body.
   - An unknown id gives a plain sentence that names the valid ids.
4. **Documents and CHANGELOG.** `docs/operations.md` shows the new output. The CHANGELOG records the change of the output of `use skill` from JSON to plain text.

No tag, marker or wrapper is added to the text.
