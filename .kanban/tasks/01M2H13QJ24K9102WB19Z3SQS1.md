## What

marketplace.md §9.2 and §9.3. Marketplace control is a host and CLI function. It is **not** a model operation: the fused `SkillsTool` gets no new operation. The `skills-demo --marketplace` mode is a separate task.

- `Sources/FoundationModelsSkills/CLI/MarketplaceCLI.swift`: an ArgumentParser `AsyncParsableCommand` named `marketplace` (ArgumentParser comes through the `Operations` re-export), with these subcommands:
  - `list` — the sources in order, with id, URL, current SHA, catalog version, last checked, and status
  - `check [<id>]` — query only
  - `update [<id>] [--force]`
  - `pin <id> <sha>` and `unpin <id>`
  - `add <url> [--ref <ref>] [--alias <alias>]` — append to the user `marketplaces.yaml` through `MarketplaceConfig.save`, so the new entry wins over earlier ones
  - `remove <id>`
- The commands build a `MarketplaceStore` from `MarketplaceConfig.load(from:includeProject:)`. The project file is read only with an explicit `--include-project` flag (the trust gate, §6.3). The cache folder comes from `MarketplaceCache.cacheDirectory(environment:)`.
- Give hosts a public way to add this command group next to the `OperationCLIDriver` tree that `SkillsCLI.makeDriver(registry:)` builds. Keep `SkillsCLI.makeDriver` unchanged.
- Errors go to standard error with a non-zero exit code.
