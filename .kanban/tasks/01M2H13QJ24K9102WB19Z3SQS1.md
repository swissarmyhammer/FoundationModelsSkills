    ### Decisions and their reasons

    - **A result type of our own.** `OperationsCLI.CLIResult` has an `internal` initializer, thus this package cannot make one. `MarketplaceCLIResult` has the same two fields, and the doc comment says so.
    - **No credential can reach the output.** `add` parses the URL before it writes, and a URL with a credential in it is no §5.1 form, thus `MarketplaceSourceError.credentialsInURL` stops it. `list` shows the normalized URL of a source that parses, and no URL at all for a source that does not. A case proves that the refusal message does not hold the token.
    - **`list` reads only the disk.** The store has no accessor for the URL, the catalog version, and the last check together, and `marketplaceLayers()` carries the `url` field as the host wrote it. The rows thus come from the configured sources plus `state.json`, over the same `MarketplaceIdentity` helpers that the store uses. `check`, `update`, `pin`, and `unpin` build a `MarketplaceStore` as the card says.
    - **The error text goes back to the host.** The package cannot print: `print` is a forbidden construct. The run gives the text and a non-zero exit code, in the same shape as `OperationCLIDriver.run(arguments:)`, and the doc says the host writes a non-zero result to standard error. A subcommand that a host runs inside its own command tree finds no session and writes to standard output through `FileHandle`.
    - **`check` and `update` with an unknown id.** `MarketplaceStore.check()` takes no id and `update(_:)` is silent about one, thus the command resolves the id to a row first and throws `MarketplacePinError.unknownMarketplace(id:)`. The exit code is then not zero.

## What

marketplace.md §9.2 and §9.3. Marketplace control is a host and CLI function. It is **not** a model operation: the fused `SkillsTool` gets no new operation. The `skills-demo --marketplace` mode is a separate task.

- `Sources/FoundationModelsSkills/CLI/MarketplaceCLI.swift`: an ArgumentParser `AsyncParsableCommand` named `marketplace` (ArgumentParser comes through the `Operations` re-export), with these subcommands:
  - `list` — the sources in order, with id, URL, current SHA, catalog version, last checked, and status

  - `pin <id> <sha>` and `unpin <id>`
